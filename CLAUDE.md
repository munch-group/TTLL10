# Protein structure viewer for notebooks

Interactive 3D protein viewer for Jupyter/VS Code notebooks, built for looking at human TTLL10
(UniProt Q6ZVT0, AlphaFold model) but usable for any protein. Owner: Kasper (kaspermunch@birc.au.dk),
a computational biologist; the notebook is his working document.

## Files

- `structure_viewer.py` — the whole viewer. `from structure_viewer import show_structure` is the main
  import. Also exports `load_structure` and `alphamissense` (per-residue scores as a list).
- `ttll10_structure.ipynb` — usage examples for TTLL10 (plus one PDB example, 1UBQ). Keep it a
  demonstration notebook: short markdown + one `show_structure(...)` per cell (the last cell demos
  `alphamissense()`), no code definitions.
  It is hand-edited now (it was originally generated by a script that no longer exists).
- `pixi.toml` / `pixi.lock` — environment: Python ≥3.11, ipykernel, jupyterlab (conda-forge).
  `pixi install`, then select `.pixi/envs/default/bin/python` as the notebook kernel, or `pixi run lab`.
- `structures/` (created at runtime, not checked in) — download cache: AlphaFold models
  (`AF-<acc>-F1-model_v*.pdb`), AlphaMissense tables (`AF-<acc>-F1-aa-substitutions.csv`), PDB entries
  (`<ID>.pdb`), `names.json` (gene name → accession) and `alphafold.json` (accession → file names).
- If git is set up: ignore `.pixi/`, `structures/`, `.ipynb_checkpoints/`, `.DS_Store`.

## Hard requirement: must work in VS Code notebooks

Kasper uses VS Code; he tests there himself (Claude could not drive VS Code in the original session).
Everything was designed around this:

- Each viewer is **plain `text/html` output** (IPython `HTML`) containing its own controls and a
  `<script>`. No ipywidgets, no py3Dmol, no nglview, no custom mime types, no kernel round-trips after
  render. The panel restyles the 3Dmol viewer in place in JavaScript, so rotation/zoom are kept.
- 3Dmol.js 2.5.5 is loaded from jsDelivr (`JS_URL`); internet is required. It is a UMD bundle: if an
  AMD loader (require.js) is present — it can be in VS Code's output webview — it registers as a module
  and never defines `window.$3Dmol`. `load3Dmol()` therefore temporarily defines `window.exports`/
  `window.module` so the bundle initialises immediately (py3Dmol's trick). Keep this.
- `whenVisible()` polls until the output box is attached and has width, because front ends attach
  output at different times; viewers created at zero size would stay blank. A `ResizeObserver` keeps
  the canvas matched to its box (`width="100%"` default).
- Mouse-wheel zoom is inverted relative to 3Dmol's default (Kasper's preference): `patchWheelZoom()`
  wraps `GLViewer.prototype._handleMouseScroll` once, before the first viewer is created (3Dmol binds
  the handler at construction), and only acts on viewers with `_ttvInvertZoom`; ctrl+wheel (trackpad
  pinch) is not inverted.
- Key presses inside the controls call `stopPropagation()` and the root has
  `data-lm-suppress-shortcuts`, so typing residue numbers does not trigger notebook shortcuts.
- All colours in the controls/legend are explicit (light panel, dark text) so they read in dark themes.

Do not reintroduce widgets, custom renderers or anything that needs a running kernel to display.

## How the code is organised (`structure_viewer.py`)

Python side:
- `load_structure(protein, organism, chain, cache_dir)` resolves the first argument: PDB ID
  (`^\d[A-Za-z0-9]{3}$`, RCSB download, one chain, first model only, ATOM records only) → UniProt
  accession (regex) → otherwise a gene/entry name looked up via UniProt REST
  (`(gene_exact:X OR id:X) AND organism_id:N`, reviewed first). Names/accessions give the AlphaFold DB
  model plus the AlphaMissense table when the API offers `amAnnotationsUrl` (human only). Cached in
  memory (`_STRUCTURES`) and on disk; an existing cache works offline.
- `alphamissense(protein, residues, organism, cache_dir)` returns `Structure.alphamissense` as a list
  (all residues in order, or those in `residues`; nan where missing). The means are kept unrounded;
  they are rounded to 3 decimals only in the viewer config.
- `Structure` dataclass: `label`, `source` (shown under the viewer), `pdb`, `residues`
  (resi → (resn, B column)), `plddt` (B column is pLDDT), `alphamissense` (resi → mean score or None).
- `expand_residues` / `parse_residues` / `compact` parse specs like `"362-365, 375"`, lists, ranges,
  pasted lists with brackets, and `"all"`. Out-of-range numbers are dropped with a printed warning.
- `show_structure(...)` builds a JSON config and fills the `__PLACEHOLDER__` slots of `VIEWER_HTML`
  (`__CSS__`, `__CONTROLS__`, `__ID__`, `__SOURCE__`, `__WIDTH__`, `__HEIGHT__`, `__CONFIG__`). The
  `</` in the JSON is escaped so `</script>` cannot break out. The PDB text is embedded per viewer
  (~450 KB per output for TTLL10).

JavaScript side (inside `VIEWER_HTML`, a raw string — backslashes are literal):
- `cfg` = the JSON config: `id, jsUrl, pdb, plddt, bLabel, am, groups, stickGroups, show, base,
  sticks (=side_chains), elements (=element_colors), labels, maxDetail, stickRadius, highlightRadius, zoom, rotation, spin, controls, fileName`.
- `init(root)` creates the viewer (`root.viewer` is the 3Dmol `GLViewer`, useful from the browser
  console), sets hover labels, and holds `state` (`groups`, `stickGroups`, `show`, `base`, `sticks`,
  `labels`). `applyStyles()` is the single place that turns `state` into 3Dmol styles, in two layers:
  1. base: cartoon and/or all-atom sticks (`stickResidues()`), coloured by `state.base` — a colour,
     `spectrum`, `plddt` (bands) or `alphamissense` (21-step gradient); property colourings are applied
     in batches via `colourGroups()`;
  2. highlights: cartoon recolour, side-chain sticks (`isSideChain`: side chain + CA, Pro keeps N)
     in the highlight colour (N/O/S by element only if `element_colors`; `elem()` builds the map), Gly as a CA sphere, labels on CA.
     Residues already drawn as sticks are recoloured whole. `detailResidues()` skips consecutive
     stretches longer than `maxDetail` (whole domains stay cartoon only; scattered residues never limited).
- `rotation=(x, y, z)` degrees = `viewer.rotate(x, "x")`, then y, then z from the default view, i.e.
  quaternion qx·qy·qz (3Dmol post-multiplies). `anglesToQuaternion`/`quaternionToAngles` convert (the
  latter via the Rx·Ry·Rz matrix; at y = ±90° everything goes into x). Applied in `init` via
  `setView` before `zoomTo` (zoomTo does not change rotation). The "Copy rotation" button copies
  `(x, y, z)` rounded to 0.1° via `navigator.clipboard`, falling back to `execCommand("copy")`, and
  prints the tuple in the message line if both fail. Rotation only — zoom/centre are not included.
- `savePNG(scale)` (Save PNG button, 4×; also `root.savePNG(n)` from the console): briefly overrides
  `window.devicePixelRatio`, which 3Dmol reads in `resize()` to size the canvas and labels, renders,
  takes `pngURI()`, restores, and downloads via a hidden `<a download>` data-URL link (VS Code should turn
  such clicks into a save dialog; not yet confirmed by Kasper). Longest side capped at 8192 px. SVG is impossible (WebGL).
- `renderLegend()` draws the footer (source line, colour key, groups with × buttons, notes);
  `wireControls()` binds the panel. `parse()` mirrors the Python residue parser for typed input.
- Python and JS deliberately duplicate the small residue-spec parser; keep them in sync.

Conventions: UK spelling in user-facing text and docstrings ("colour"), US spelling in identifiers
and CSS (`color`). Docstring of `show_structure` is the reference for all options — update it with
any API change. Argument names are part of the API Kasper uses in his notebook; renaming needs a note.

## Testing (do this before handing anything over)

1. Headless run of the notebook in the pixi env (catches Python errors, warnings, escaping mistakes):
   `pixi run jupyter nbconvert --to notebook --execute ttll10_structure.ipynb --output /tmp/executed.ipynb`
   then check that no output has `output_type == "error"` or stderr text.
2. Live check in JupyterLab (the JS cannot be tested headlessly). Start
   `pixi run jupyter lab --no-browser --LabApp.expose_app_in_browser=True` and drive it from the
   browser console / browser tool:
   `window.jupyterapp.commands.execute('notebook:run-all-cells')`, then inspect
   `document.querySelectorAll('.ttv')` — each has `.viewer` (3Dmol) and `.ttv-msg` (empty = OK, else
   the error). Atom styles are inspectable via `viewer.getModel().selectedAtoms({})` (`a.style.stick`,
   `a.style.cartoon.color`); `viewer.pngURI()` gives a screenshot of the canvas.
   Note: in a hidden browser pane rendering is throttled, so `innerText`/ResizeObserver checks can
   lag; use `textContent` and poll.
3. VS Code cannot be driven by Claude here. The closest stand-in used before: a static HTML page
   that loads require.js and inserts the notebook's `text/html` outputs the way VS Code's renderer
   does (innerHTML into a div, append, then re-create each `<script>`), served with
   `python -m http.server` (Jupyter's `/files/` blocks it). Final VS Code verification is Kasper's.
4. Network-dependent code (`_resolve_name`, `_alphafold_model`, `_pdb_entry`) was tested against the
   live services; retest with a fresh `cache_dir` and once with `urllib.request.urlopen` patched to
   raise, to prove the offline path.

## Data caveats worth remembering

- The "ATP-binding residues" 362–365, 375, 377 used in the examples are UniProt binding-site features
  inferred by similarity (ECO:0000250) from TTLL7 (Q6ZT98); TTLL10 is annotated as an inactive
  polyglycylase. Say "residues aligned to TTLL7's ATP site" if precision matters.
- Residue numbers are model numbering: UniProt numbering for AlphaFold; author numbering for PDB
  entries (insertion codes are ignored, HETATM/ligands are dropped).
- 17 of Kasper's residues of interest (3–153, 574–636) lie in low-pLDDT loops far from the core.
- AlphaMissense per-residue value = mean over the 19 substitutions (what AlphaFold DB shows); the
  file is only available for human entries.
